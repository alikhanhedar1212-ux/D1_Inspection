# USB 麦克风语音导航

链路：AidLux USB 麦克风 → PulseAudio 16 kHz 单声道录音 → SSH → 本机离线 Vosk 中文识别 → Nav2 NavigateToPose → 现有 velocity_bridge → Firefly。

本机目录：`./voice_navigation`。
远端录音脚本：`~/D1_Inspection/voice_navigation/audio_sender.py`。
模型来自 https://alphacephei.com/vosk/models ，使用 `vosk-model-small-cn-0.22`。
音频不提交给云端。识别结果写到本机 `status.json`，终端也会输出。

## 实时文字页面

地址： http://127.0.0.1:8091/ 。显示实时识别文字、最终识别记录、唤醒状态、10 秒窗口及最近指令。无论是否唤醒，都进行文字转写；导航指令仍遵守原有唤醒限制。

启动页面服务（监听程序需单独启动）：
```bash
python3 ./voice_navigation/voice_dashboard.py
```
页面默认监听所有 IPv4 网卡，同一局域网内可通过 `http://电脑局域网IP:8091/` 访问；本机仍可使用上述地址。若需仅限本机，启动时加 `--host 127.0.0.1`。识别事件保存在本地 `ui_events.jsonl`，无外部字体、脚本或网络依赖。“清空显示”只清空当前页面记录，不删除文件。

## 先测试识别

### 在本机测试，不连接机器狗

```bash
bash ./voice_navigation/run_local.sh
```

使用电脑当前默认麦克风和扬声器，无需 ROS 或 SSH。说“太乙真人”，电脑播放“我在”；回复后 10 秒内说“去一号位置”或其它已有指令，电脑播放“好的”，终端打印解析结果，不触发移动。超时需要重新唤醒，按 Ctrl+C 退出。

接入 USB 麦克风后，可以在系统声音设置选为输入，或使用 `--source` 指定 `pactl list short sources` 中的完整设备名。麦克风在电脑或 AidLux 上时，使用同一模型和唤醒逻辑；实际距离、噪声和增益需在机器狗上复测。

Newmine 当前使用 `newmine_noise_profile.npz` 做实时背景噪声抑制，按 100 毫秒音频块处理。该配置来自本机 Newmine 97% 输入音量时采集的背景噪声；修改增益、换 USB 口或回到机器狗后，需要核对噪声配置是否仍适用。现有含噪录音经过实时算法后已两次正确识别“太乙真人”，现场实时效果仍需测试。

实机模式使用单独校准的 `newmine_noise_profile_remote.npz`，本机模式继续使用 `newmine_noise_profile.npz`，两者不会互相覆盖。已保存 aidlux 环境的背景噪声配置，供远端麦克风模式使用。当前使用电脑收音、机器狗播报模式。

后台测试时日志在 `listener.log`，PID 在 `listener.pid`；更换本机/远端模式前先停止旧监听，程序拒绝重复启动。

### 使用 AidLux 麦克风

### 电脑收音，机器狗播报

```bash
bash ./voice_navigation/run_computer_mic.sh
```

电脑接入 Newmine ZM12 并将其设为默认输入，或用 `--source` 指定设备。电脑离线识别“太乙真人”后，通过 SSH 调用 aidlux 播放“我在”；10 秒内收到有效指令，在机器狗播放“好的”。默认仍只演示识别和回复，不触发移动。本机噪声配置复用 `newmine_noise_profile.npz`。实际导航可使用同模式加 `--execute`，仍需先确认地图点位及现有导航系统状态。

已确认输入为 Newmine（纽曼）ZM12 USB 麦克风，生产厂家为北京纽曼腾飞科技有限公司。

```bash
bash ./voice_navigation/run.sh
```

默认只识别，不发送运动目标。先说“太乙真人”，机器狗回答“我在”。从回复播放完毕开始有 10 秒可以说一个完整指令，说完停顿一下：

- 去一号位置 / 去 1 号点 → 1 正门
- 去门口 → 1 正门
- 去洗手间门口 / 去卫生间 → 2 洗手间
- 去放映厅 → 3 放映厅
- 去展示厅起点 / 去展示区起点 → 4 展示区起点
- 去展示厅中心 → 5 展示区中心
- 去窗边 → 6 窗户
- 停止 / 停下 / 取消导航 → 取消目标并调用现有停止服务（执行模式）

也支持二号至六号。模糊、多目的地、否定语句不执行。

有效指令一旦识别就立即处理，并从收到指令的时刻重新计时 10 秒；期间可连续发送指令，无需重复唤醒。只有连续 10 秒没有收到有效指令才回到待唤醒状态，需重新说“太乙真人”。无关话语不会延长窗口。“停止”“停下”“取消导航”无须唤醒，在执行模式随时可用。播放“我在”时不识别音频，断线后清除唤醒状态。待唤醒时使用包含未知词拒识的限定词表，唤醒后使用完整中文模型识别目的地。

查看远端麦克风：`ssh aidlux 'pactl list short sources'`。
指定其它输入：`bash run.sh --source 完整PulseAudio输入源名称`，不能选择 `.monitor` 输出回环。

## 启用实际导航

先启动现有 AidLux 传感器输入、本机导航和 `velocity_bridge.py`，在 RViz 设置并确认实时定位。
点位配置复用 `../navigation_localization/waypoints.yaml`。其中位置目前标记 `confirmed: false`，需逐个在现场核对坐标和朝向后改为 `true`；未确认点位会拒绝运动。

```bash
bash ./voice_navigation/run.sh --execute
```

识别最终结果且词置信度至少 0.65 才执行。每次只接收一个目的地，正在执行本程序目标时，先说停止再更换目的地。沿用现有导航避障、限速和定位质量保护。首次启动不恢复旧语音目标，音频断线丢弃未完成识别结果，重连后需重新说指令。退出本程序时取消本程序仍在执行的目标。

## 语音查询电量（2026-10-23）

唤醒“小爱小爱”，听到“我在”后说“还剩多少电”“还有多少电”“查询电量”或“电池电量”。每次在Firefly原生battery_state通道读取至少两帧新数据，校验来源、时间、百分比范围和有效电压，再经AidLux本地语音引擎播报“当前电量百分之……”。不使用历史缓存替代失败结果；数据不可用时播报“暂时无法读取电量，请稍后再试”。

只读查询不取消正在执行的导航，不修改姿态、电量或充电控制；“停止”可取消查询。播报期间抑制自身回声并保留停止识别。读取程序~/D1_Inspection/voice_navigation/read_battery_native，播报~/D1_Inspection/voice_navigation/battery_reply.py，状态battery_status.json。沿用40%音量，按百分比缓存语音。原始电流为uint32回绕值、厂商error位含义尚未解析，本功能不据此判断充电状态或电池健康，仅播报power百分比。
